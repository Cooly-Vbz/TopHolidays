# Top Holidays - Complete PWA E-commerce Application

## PROJECT OVERVIEW
Build a Progressive Web App (PWA) e-commerce store called "Top Holidays" that sells holiday-themed clothing products via Print-On-Demand integration with Shopify. The app must be installable on all devices, highly secure, privacy-focused, and feature a complete guest/authenticated user experience with a digital coins reward system.

---

## CRITICAL TECHNICAL REQUIREMENTS

### PWA Configuration
**IMPORTANT: Follow these exact steps for PWA setup**

1. **Manifest.json Configuration:**
   - Generate complete manifest.json at root level
   - Required icons: 192x192, 512x512, 144x144, 96x96, 72x72, 48x48 (PNG format)
   - Set `"display": "standalone"` for full-screen experience
   - Set `"start_url": "/"` to specify entry point
   - Set `"theme_color"` and `"background_color"` matching brand
   - Add `"orientation": "any"` for flexible device support
   - Include `"scope": "/"` to define service worker scope

2. **Service Worker Implementation:**
   - Register service worker at root level (not in subdirectory)
   - Implement install event: cache critical assets during installation
   - Implement activate event: clean up old caches
   - Implement fetch event: intercept requests for offline support
   - Use versioned cache names (e.g., 'top-holidays-v1')
   - Cache strategy: Network-first for API calls, Cache-first for static assets
   - CRITICAL: Register service worker AFTER page load to avoid blocking:
   ```javascript
   if ('serviceWorker' in navigator) {
     window.addEventListener('load', () => {
       navigator.serviceWorker.register('/sw.js')
         .then(registration => console.log('SW registered'))
         .catch(err => console.log('SW registration failed'));
     });
   }
   ```

3. **iOS PWA Support:**
   - Add apple-touch-icon links in HTML head (180x180 minimum)
   - Add `<meta name="apple-mobile-web-app-capable" content="yes">`
   - Add `<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">`
   - Add `<meta name="apple-mobile-web-app-title" content="Top Holidays">`

4. **Offline Functionality:**
   - Cache all HTML, CSS, JS files during service worker install
   - Cache product images progressively as user browses
   - Display custom offline page if network unavailable
   - Queue failed API requests for retry when online
   - Show connection status indicator to user

### Performance & Architecture
- Build as a Single Page Application (SPA) with client-side routing
- Implement code splitting and lazy loading for optimal performance
- Minimize server requests by caching product data locally
- Use React Query or similar for efficient data fetching and caching
- Optimize all images with lazy loading and WebP format where possible

### Security & Encryption Implementation
**⚠️ CRITICAL SECURITY WARNING: This section addresses CVE-2025-48757 vulnerability**

Lovable apps using Supabase are vulnerable to data exposure if Row Level Security (RLS) policies are missing or insufficient. The Security View in Lovable displays findings from database security advisors and AI-powered reviews of RLS policies, but you MUST manually verify security.

**MANDATORY SECURITY STEPS - DO NOT SKIP:**

1. **Row Level Security (RLS) - HIGHEST PRIORITY:**
   Enable RLS on ALL tables immediately using: `ALTER TABLE schema_name.table_name ENABLE ROW LEVEL SECURITY;`
   
   **Required RLS Policies for Each Table:**
   ```sql
   -- Users table: users can only access their own data
   CREATE POLICY "Users can view own data" ON users
     FOR SELECT USING (auth.uid() = id);
   
   CREATE POLICY "Users can update own data" ON users
     FOR UPDATE USING (auth.uid() = id);
   
   -- Orders table: users can only see their own orders
   CREATE POLICY "Users can view own orders" ON orders
     FOR SELECT USING (auth.uid() = user_id);
   
   CREATE POLICY "Users can insert own orders" ON orders
     FOR INSERT WITH CHECK (auth.uid() = user_id);
   
   -- Favorites table: users can only access their favorites
   CREATE POLICY "Users can manage own favorites" ON favorites
     FOR ALL USING (auth.uid() = user_id);
   
   -- Cart table: users can only access their cart
   CREATE POLICY "Users can manage own cart" ON cart_items
     FOR ALL USING (auth.uid() = user_id);
   
   -- Digital wallet: users can only access their wallet
   CREATE POLICY "Users can view own wallet" ON digital_wallets
     FOR SELECT USING (auth.uid() = user_id);
   ```

2. **Verify RLS in Supabase Dashboard:**
   - Go to Authentication > Policies in Supabase
   - Check that every table has RLS enabled and policies defined
   - Test policies by attempting unauthorized access
   - Use Lovable's Security Reviewer to analyze your entire app for vulnerabilities

3. **API Key Protection - CRITICAL:**
   Never put API keys in frontend code; store them in environment variables or Supabase Edge Functions
   
   **Safe API Key Usage:**
   - Store Shopify API keys in Supabase Secrets (not in code)
   - Use Supabase Edge Functions for sensitive operations
   - Never expose private keys in client-side code
   - Rotate keys regularly
   
   **Create Edge Function for Secure Operations:**
   ```typescript
   // Supabase Edge Function: /functions/secure-payment/index.ts
   import { serve } from "https://deno.land/std@0.168.0/http/server.ts"
   
   serve(async (req) => {
     // API key stored in Supabase Secrets, not in code
     const apiKey = Deno.env.get('SHOPIFY_API_KEY')
     
     // Verify user is authenticated
     const authHeader = req.headers.get('Authorization')
     if (!authHeader) {
       return new Response('Unauthorized', { status: 401 })
     }
     
     // Your secure logic here
   })
   ```

4. **Client-Side Encryption (Additional Layer):**
   While RLS is mandatory, add encryption for sensitive fields:
   
   ```javascript
   // Use Web Crypto API for sensitive data encryption
   async function encryptData(data, userPassword) {
     const enc = new TextEncoder();
     const keyMaterial = await crypto.subtle.importKey(
       "raw",
       enc.encode(userPassword),
       { name: "PBKDF2" },
       false,
       ["deriveKey"]
     );
     
     const key = await crypto.subtle.deriveKey(
       {
         name: "PBKDF2",
         salt: enc.encode("unique-salt-per-user"),
         iterations: 100000,
         hash: "SHA-256"
       },
       keyMaterial,
       { name: "AES-GCM", length: 256 },
       false,
       ["encrypt", "decrypt"]
     );
     
     const iv = crypto.getRandomValues(new Uint8Array(12));
     const encrypted = await crypto.subtle.encrypt(
       { name: "AES-GCM", iv: iv },
       key,
       enc.encode(JSON.stringify(data))
     );
     
     return { encrypted, iv };
   }
   ```

5. **Database Synchronization with Security:**
   - Store encrypted data on server with user's encryption key
   - Use IndexedDB for local encrypted storage
   - Implement conflict resolution: timestamp-based with user confirmation
   - **CRITICAL:** On CRUD operations:
     - Check user authentication FIRST
     - Verify RLS policies allow operation
     - Compare local and server data hashes
     - Sync differences only for authenticated user's data
   - Queue offline operations securely
   - Validate all data before syncing

6. **Input Validation & Sanitization:**
   Implement input validation to prevent SQL injection, XSS, and file upload attacks
   
   - Sanitize all user inputs before database operations
   - Use parameterized queries (Supabase does this automatically)
   - Validate file uploads (type, size, content)
   - Implement Content Security Policy (CSP) headers
   - Escape HTML in user-generated content

7. **Authentication Security:**
   - Password requirements: minimum 12 characters, mixed case, numbers, special chars
   - Use bcrypt or Argon2 for password hashing (Supabase handles this)
   - Implement rate limiting: max 5 login attempts, then 15-minute lockout
   - Session timeout: 30 minutes of inactivity
   - Require 2FA for sensitive operations (profile changes, large purchases)
   - Implement CSRF protection tokens

8. **HTTPS & Transport Security:**
   - Enforce HTTPS for all connections (Lovable does this automatically)
   - Use TLS 1.3 for all data transmission
   - Implement HTTP Strict Transport Security (HSTS) headers
   - Set secure cookie flags (HttpOnly, Secure, SameSite)

### Shopify Integration

**Complete Setup Instructions:**

1. **Initial Shopify Setup:**
   - Create Shopify account at shopify.com
   - For development: Use Shopify Partner account to create development stores (free)
   - For production: Use your actual Shopify store
   - Enable Shopify Admin API access

2. **Connect Lovable to Shopify:**
   - In Lovable: Go to Integrations menu → Select Shopify
   - Authorize Lovable to access your Shopify store
   - Provide: Store URL, Admin API access token
   - Test connection by fetching a sample product

3. **Configure Shopify for Print-On-Demand:**
   - Install Print-On-Demand app from Shopify App Store (e.g., Printful, Printify)
   - Connect POD provider account
   - Create product catalog with holiday-themed designs
   - Set up product variants (sizes, colors)
   - Configure shipping zones and rates
   - Set up tax calculations

4. **Product Synchronization:**
   - Use Shopify Storefront API (not Admin API) for frontend
   - Fetch products with GraphQL queries:
   ```graphql
   query {
     products(first: 50) {
       edges {
         node {
           id
           title
           description
           priceRange {
             minVariantPrice {
               amount
               currencyCode
             }
           }
           images(first: 5) {
             edges {
               node {
                 src
                 altText
               }
             }
           }
           variants(first: 10) {
             edges {
               node {
                 id
                 title
                 priceV2 {
                   amount
                 }
                 availableForSale
               }
             }
           }
         }
       }
     }
   }
   ```

5. **Cart & Checkout Implementation:**
   - Use Shopify's cart management system
   - Create cart with Storefront API: `checkoutCreate` mutation
   - Add items: `checkoutLineItemsAdd` mutation
   - Update quantities: `checkoutLineItemsUpdate` mutation
   - Remove items: `checkoutLineItemsRemove` mutation
   - Redirect to Shopify checkout URL for payment
   - Handle post-purchase webhooks for order confirmation

6. **Inventory Management:**
   - Real-time inventory sync from Shopify
   - Display "Out of Stock" for unavailable items
   - Update cart if items become unavailable
   - Set up low-stock alerts

7. **Order Management:**
   - Fetch customer orders via Shopify Customer API
   - Display order history in Orders page
   - Provide order tracking information
   - Handle refunds through Shopify Admin

8. **Shopify Webhooks Setup:**
   - Configure webhooks for: orders/create, orders/updated, products/update
   - Create Supabase Edge Function to receive webhooks
   - Update local database when orders/products change
   - Validate webhook signatures for security

**Important Shopify Security:**
- Never expose Admin API tokens in frontend code
- Use Storefront API tokens (public) for frontend
- Store Admin API tokens in Supabase Edge Functions
- Validate all cart operations on Shopify side
- Implement webhook signature verification

## DIGITAL COINS REWARD SYSTEM

### Earning Coins
- Only promoted products (⭐ icon) offer coins
- Earn: Product price × 10 coins per purchase
- Example: $25 product = 250 coins earned
- Coins credited after order confirmation

### Spending Coins
- 1 coin = $0.01 value
- Can buy promoted products with coins only
- Cost: Product price × 100 coins
- Example: $25 product = 2,500 coins to purchase
- Mixed payment: coins + cash allowed

### Wallet Display
- Real-time balance in sidebar
- Transaction history in account settings
- Expiration warnings (if coins expire)
- Coins are transferable between any promoted products

### Business Logic
**Important:** This creates customer loyalty by requiring 10 purchases of promoted items to earn enough for one free promoted item. Users can mix and match - buy one promoted product 10 times, or 10 different promoted products once each, to earn enough coins for any single promoted product.

### CRITICAL: Pre-Deployment Security Checklist

**⚠️ DO NOT DEPLOY until ALL items are checked and verified:**

#### Database Security (HIGHEST PRIORITY)
- [ ] Run `SELECT tablename FROM pg_tables WHERE schemaname = 'public'` in Supabase SQL editor to list all tables
- [ ] For EACH table, verify RLS is enabled: `SELECT tablename, rowsecurity FROM pg_tables WHERE schemaname = 'public'`
- [ ] For EACH table, verify policies exist: `SELECT * FROM pg_policies WHERE schemaname = 'public'`
- [ ] Manually test unauthorized access: create second test user, try to access first user's data
- [ ] Verify unauthenticated users cannot access any user data
- [ ] Test that users can ONLY access their own data (user_id = auth.uid())
- [ ] Check that admin operations require admin role (if applicable)
- [ ] Run Lovable's Security Review and resolve ALL errors and warnings
- [ ] Use browser dev tools network tab: verify no sensitive data in API responses for other users

#### API Key & Secrets Security
- [ ] Search entire codebase for hardcoded API keys (search for common patterns: "api_key", "secret", "token")
- [ ] Verify Shopify Admin API token is ONLY in Supabase Edge Functions, not in frontend
- [ ] Verify all environment variables are properly configured in hosting platform
- [ ] Check that .env files are in .gitignore (not committed to Git)
- [ ] Rotate any API keys that were accidentally exposed
- [ ] Verify API keys have minimum required permissions (principle of least privilege)
- [ ] Test that frontend still works without admin API keys (should use public Storefront API)

#### Authentication & Authorization
- [ ] Test password requirements are enforced (12+ chars, mixed case, numbers, special)
- [ ] Test rate limiting: attempt 6 failed logins, verify 15-minute lockout
- [ ] Test session timeout: leave app idle 30 minutes, verify user logged out
- [ ] Test 2FA (if enabled): verify codes are required and validated
- [ ] Test password reset flow end-to-end
- [ ] Verify email verification is required (if implemented)
- [ ] Test that user cannot access protected routes when logged out

#### Input Validation & Injection Prevention
- [ ] Test SQL injection: try `' OR '1'='1` in all input fields
- [ ] Test XSS: try `<script>alert('XSS')</script>` in all text inputs
- [ ] Test file uploads: try uploading .exe, .php, oversized files
- [ ] Verify all user inputs are sanitized before display
- [ ] Test that HTML in user content is escaped
- [ ] Verify Content Security Policy headers are set
- [ ] Test that URLs in user content are validated

#### HTTPS & Transport Security
- [ ] Verify entire site runs on HTTPS (no mixed content warnings)
- [ ] Check that cookies have Secure and HttpOnly flags
- [ ] Verify HSTS headers are set
- [ ] Test that HTTP requests redirect to HTTPS
- [ ] Verify WebSocket connections use WSS (if applicable)

#### PWA Security
- [ ] Verify service worker only caches public assets (no sensitive data)
- [ ] Check that service worker doesn't expose API keys
- [ ] Test offline mode doesn't leak other users' data
- [ ] Verify cached data respects authentication (cleared on logout)
- [ ] Test that service worker updates properly with new versions

#### Business Logic Security

- [ ] Test that discount codes are validated properly
